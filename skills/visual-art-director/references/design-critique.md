# 设计评审与反 AI 味清单（Design Critique）

终稿交付前逐项过。评审顺序不能反：先看"一眼"，成立了再细看，最后查专业项。

## 第一层：3 秒一眼（不成立直接返工）

- [ ] 主题 3 秒内看得懂，不需要阅读说明文字
- [ ] 第一眼只有一个落点（主体或主标题），没有两个元素在抢
- [ ] 缩略图测试：画面缩到 25%，主体轮廓和标题仍然清晰
- [ ] 在发布平台的信息流里（深色/浅色界面）扫一眼，能从周围内容中跳出来

## 第二层：层级与表达

- [ ] 信息按"标题 → 副标题/卖点 → 行动信息 → 注解"明确分层，字号差至少 2.5 倍
- [ ] 弱信息靠明度/颜色降级，而不是缩到看不清
- [ ] 一张图主卖点不超过 3 个；主图建议 1 个
- [ ] 颜色承担分层职责（60-30-10），不是所有元素一个颜色，也不是每个元素不同色
- [ ] 留白率：品牌/高端稿 ≥ 30%，促销稿 ≥ 15%；没有元素贴边、挤压、互相碰撞
- [ ] 所有文字块有至少一条共同的对齐线；左检查、右检查、中线检查各看一遍
- [ ] 正文对比 ≥ 4.5:1，大字 ≥ 3:1；文字在任何背景区域都可读（必要时加 scrim 或色块）
- [ ] CTA/二维码/价格位置明显，拇指热区可达（手机端）

## 第三层：专业项

- [ ] 尺寸精确匹配发布位（见 china-platform-sizes.md），关键内容在安全区内
- [ ] 光源方向全图统一，投影方向、虚实、色温一致
- [ ] 图标线宽一致、风格一致（线性/面性不混）；不用 emoji 充当正式图标
- [ ] 圆角、描边、阴影、间距取自同一套尺度（如 4/8/12/16/24），没有随机数值
- [ ] 字体 ≤ 2 个家族；中文走了中文字体栈，没有意外回落到衬线默认体
- [ ] 数字/价格用西文与 tabular-nums；全角标点、避头尾正确
- [ ] AI 底图没有乱码文字、畸形手/物体、违和拼接；商品没有被模型重绘变形
- [ ] 文案、价格、日期、地址、电话、Logo、平台标志、极限词已人工核对
- [ ] 同组物料（详情页多屏、轮播多页）字体/角标/编号/色板完全统一
- [ ] 输出格式正确：印刷 CMYK + 300dpi + 出血；屏幕 PNG/JPG；透明素材 PNG/WebP

## 反 AI 味对照表（高频廉价感来源与修法）

| 廉价感来源 | 典型表现 | 修法 |
|-----------|---------|------|
| 默认紫蓝渐变 | #667eea→#764ba2 这类 135° 蓝紫铺满 | 从品牌/行业定色相，写死两个以上 hex；试试单色相明暗、低饱和双色 |
| 模糊光斑三件套 | 两三个 blur(60px) 彩色圆 + 玻璃卡 | 删掉光斑，用留白和字体对比；玻璃仅在深色确实需要分层时保留 |
| 满屏居中 | 标题、图、按钮全部正中堆叠 | 改非对称：贴边、出血、对角线组织、60/40 分割 |
| 装饰多于信息 | 漂浮几何、线条、粒子到处都是 | 每个装饰问一句"它在引导视线吗"，答不上就删 |
| 圆角泛滥 | 所有元素 16-24px 圆角 | 大容器小圆角（4-8px）或直角；只在需要亲和的元素上圆 |
| 重投影 | 多层黑色大模糊阴影 | 改极淡柔光（rgba 黑 6-12%，模糊 16-24px）或 1px 描边分层 |
| 高饱和撞色满屏 | 红黄蓝紫同时高彩 | 底色降饱和到 60% 以下，只留一个高彩度强调 |
| 三种字体混搭 | 标题宋、正文圆、数字花 | 固定 2 个家族，用字重和字号制造变化 |
| 假大词英文装饰 | 无意义的 LUXURY/MODERN/DESIGN 水印字 | 删除，或换成与信息相关的栏目名/序号 |
| 图标不统一 | emoji + 线图标 + 实心图标混用 | 选一套图标库统一线宽；emoji 只允许在活泼风格里偶尔出现 |
| 商品悬浮无投影 | 抠图后直接贴，像贴纸 | 加与光源一致的接触阴影（椭圆渐变 + 模糊） |
| 文字压在乱背景上 | 标题区域什么颜色都有 | 标题区加纯色块/毛玻璃/压暗渐变，或出图时就预留干净留白 |
| 比例失调 | 元素大小接近、没有主次 | 主元素做到次元素的 2 倍以上；价格/数字敢做到 5 倍 |

## 用户说"没感觉"时的诊断顺序

1. 风格锚点是否具体？（"简约大气"不是锚点，"瑞士网格 + 单红强调"才是）→ 回 style-taxonomy.md 重选
2. 对比是否不够？（字号差、明度差、色相差三选一拉开）
3. 是否太满？（删 30% 元素再看）
4. 质感是否假？（光向统一、材质具体、颗粒克制）
5. 文案是否本身不成立？（设计救不了平庸的主标题，先改文案再改图）

## 迭代纪律

- 一轮只改一个变量，改完让用户确认，避免多轮后风格漂移
- 保留每轮版本文件（_v1/_v2），终稿单独放 final/
- 每次返工记录原因（构图/配色/字体/质感/文案），同类问题在同组物料中一次性修完
